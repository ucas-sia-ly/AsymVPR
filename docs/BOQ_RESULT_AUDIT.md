## 已确认的实验条件差异

| 项目 | 当前任务 | 原论文 / 官方发布权重 |
| --- | --- | --- |
| DINOv2 训练尺寸 | 224×224，16×16 patches | 论文 §4.5：280×280，20×20 patches |
| 聚合器通道 / heads | 512 / 8 | 发布权重：384 / 6 |
| 行投影 / 描述子维度 | 16 / 8192 | 发布权重：32 / 12288 |
| 训练地点 | 本地原始 64,394，≥4 图后 62,514 | 论文概述约 67k，未提供逐地点对照清单 |
| 训练图片 | 本地原始 529,506，≥4 图后 524,701 | 论文概述约 560k，版本及筛选范围不能精确对齐 |
| 验证集 | MSLS-val 740 查询，Pitts30k-val 7,608 查询 | 表 9 的 Pittsburgh 数值是 test，非当前 val |

模型形状通过读取本地训练检查点与官方 `dinov2_12288.pth` 直接核实，非根据名称猜测。
仓库 train.py 的默认值确实为 224、512 通道和 8192 维，但这些默认值不等于发布模型或论文配置。
此前把“对齐官方源码默认配置”泛化为“与论文一致”不够准确。

主文 §4.2 还列出 lr=2e-4～4e-4、weight decay=1e-3、3 epochs 预热、每 5～10 epochs
乘 0.3；当前默认脚本为 1e-4、1e-4、10 epochs 预热、10/20 epochs 乘 0.1。
§4.2 主要讲 ResNet 实验；不能据此断言 DINOv2 的精确最终配方，或擅自拼接为“完整官方论文配置”。

## 代码与运行检查

- 小型 CPU 输入：同权重下，本地 BoQ 默认 attention 路径与原始源码前向、参数梯度最大误差均为 0。
  这是局部实现检查，不能代替完整 GPU 训练等价性证明。
- 实际日志：首步 lr=2.04499e-8，第 1 轮末 lr=1e-5，step 4880 为 9.97955e-5；
  第 10 轮末调度后为 1e-5，第 20 轮末为 1e-6。预热和衰减与当前默认配方一致。
- checkpoint 的 global_step=16,626，而优化器实际更新 16,623 次；AMP 有 3 次跳过。
  没有记录到非有限 loss，目前无证据表明这是主要差距来源。
- 每轮 62,514 地点、每地点 4 张、共 250,056 图，489 步且保留尾批；没有因内存修复缩小 batch。
- 采样按城市分组。当前城市按缓存字母序排列，上游按文件系统 glob 顺序，实际次序不同；
  当前使用独立的 epoch/batch 随机生成器，上游为 Pandas/NumPy 全局随机序列。
  不能宣称 seed=2024 就使整个样本序列逐位一致；影响量尚未隔离。
- 流式验证仍为完整图库的精确 L2 检索，回归测试与整体 FAISS 检索一致。
  验证的 uint8 Resize 与当前上游 datamodule 一致，但不同于发布权重 README 的
  ToTensor→浮点 Resize；在一张真实图片上归一化张量平均绝对差约 0.00514。
  仅凭这个输入差不能判断造成多少 Recall 差距。

## 结论与后续顺序

已证实当前实验不是论文 DINOv2 发布模型的同配置复现；尚未量化各项差异的因果贡献。
先保留本次 8192 维基线，完成既定训练并使用自动选择的最佳检查点报告结果。
再统一评测预处理和协议，对现有官方权重与本地最佳权重进行同协议评测，隔离评测差异；
如需重训，再建立 384 通道、12288 维、280 输入的独立实验，并明确学习率日程的来源。
不能把一次同时改变多项设置后的提升归因于单一因素，也不能保证必达 93.8%。
本轮只做只读检查和 CPU 局部数值核对，没有修改正在运行的训练、停止任务或启动新训练。
